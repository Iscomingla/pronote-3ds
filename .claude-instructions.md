# Instructions for Claude AI

## Read before acting
- Always re-fetch files before editing — other changes may have happened since your last pull.
- Check `.claude-instructions.md` for updates at the start of every session.

## Git workflow
- **Never push directly to `main`.** Always create a new branch and open a PR.
- Before adding commits to an existing PR, check it hasn't been closed or merged already.

## Fixing bugs
1. Add the bug/task to `TOFIX.md` before starting work and push it directly to `main` (prompts get interrupted).
2. Fix it in a new branch.
3. Remove it from `TOFIX.md` in `main` once done.

## To-do list
- Use `TODO.md` to track features and tasks. Keep it up to date.

## Project context
- **Target:** Nintendo 3DS homebrew (`.3dsx`), built with devkitARM.
- **Language:** C (ARM, `-march=armv6k`).
- **Build system:** devkitPro Makefile (`make`). Entry point: `src/main.c`.
- **Key libs:** libctru (3DS SDK). No portlibs assumed to be available.

## Vendored libraries
- **quirc** (QR decoder) is vendored under `lib/quirc/` — do NOT treat it as an external dependency or suggest installing it.
- If a library is missing from devkitPro portlibs, vendor it the same way (copy sources into `lib/<name>/`, add the directory to `SOURCES` in the Makefile, add `lib` to `INCLUDES`).

## Makefile rules
- `SOURCES` lists directories scanned for `.c`/`.cpp` files — add new source dirs here.
- `INCLUDES` lists directories scanned for headers — add `lib` to expose vendored lib headers.
- `LIBS` should only list libs that are actually installed (currently `-lctru -lm`). Do not add `-l<lib>` for vendored code.
- Do not use `$(PORTLIBS)` or hardcode `/opt/devkitpro` paths — they are unreliable in this setup.

## What NOT to do
- Do not suggest `pacman -S` or any package install — assume all dkp packages are already installed.
- Do not use `$(PORTLIBS)` in `LIBDIRS` or `CFLAGS`.
- Do not push to `main` directly except if clearly said.
